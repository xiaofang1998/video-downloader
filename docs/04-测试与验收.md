# 04 测试与验收

## 1. 测试策略

| 原则 | 做法 |
| --- | --- |
| **离线可跑** | 所有 HTTP 交互打**本地服务器**（`tests/conftest.py` 的 `sample_server`），自动化测试不发真实外网请求 |
| **不碰用户环境** | 不读写真实浏览器 cookie（`test_cookies.py` 全部用临时假 profile）、不起真浏览器、不装证书 |
| **能断言的才自动化** | 需要登录/风控/真实链路的结论 → 写进本文档的"人工验收清单" |
| **回归钉住坑** | 每个踩过的坑都补一条测试，并在测试 docstring 里写清"为什么"（例如 `test_inject_js_is_read_only_and_inert`） |
| **真机验证关键路径** | ffmpeg 擦水印、打包产物、真实链接下载 → 实际操作一遍（第 4 节） |

## 2. 怎么跑

```bat
:: 全部（约 1～3 分钟）
.venv\Scripts\python.exe -m pytest -q

:: 单个文件
.venv\Scripts\python.exe -m pytest tests/test_downloader.py -q

:: 按关键字
.venv\Scripts\python.exe -m pytest -q -k "watermark or delogo"

:: 离线自检（附带端到端烟测，起本地服务跑一遍全链路）
.venv\Scripts\python.exe run.py selftest

:: 环境体检（代理/引擎/上传通道/数据库/视频号链路）
.venv\Scripts\python.exe run.py doctor
```

## 5. 已知缺口与偶发用例

| 项 | 说明 | 处理建议 |
| --- | --- | --- |
| `test_series.py` 的两个 E2E 偶发失败 | `test_series_partial_failure_reply_reveals_shortfall`、`test_series_uses_series_done_reply` 在整包跑时偶发失败，单跑通过（时序相关） | 重跑确认；后续把它们改成用事件等待而非固定 sleep |
| 视频号真实下载依赖元宝登录态 | 元宝会话过期时链路会失败（提示去元宝登录） | 过期时重跑 `run.py channels-login --yuanbao` |
| 抖音/TikTok 依赖登录态有效 | 登录态失效后需要重新 `cdp-login` | 错误文案已提示 |
| X 镜像接口是第三方服务 | fxtwitter 可能变 | 双镜像降级 + 宽容解析；失败时如实报错 |
| 抓包通道无自动化真机测试 | 需要微信客户端配合 | 保留手动流程，见 [05 排障](05-部署与排障.md) |
| ffmpeg 相关测试在无 ffmpeg 的机器上跳过 | `pytest.skip("没有 ffmpeg")` | 打包版自带 ffmpeg，源码运行需自行安装 |

## 7. 测试里刻意保留的"坑注释"

很多测试的 docstring 写的不是"断言什么"，而是**"为什么要有这条断言"**，例如：

- `test_event_loop_rejects_stale_cancel_flag` —— 取消标志与终态写入的竞态（客户会被"取消不了"卡住）
- `test_leaf_cert_concurrent_signing` —— 微信并发建连导致证书私钥互相覆盖（整轮抓包零捕获）
- `test_upstream_with_scheme_is_parsed` —— 链式上游带 `http://` 前缀被当成主机名（**曾导致用户断网**）
- `test_order_episode_range_only_affects_that_order` —— 选集写全局配置会串单
- `test_inject_js_is_valid_javascript` —— 探测表混进保留字，整段注入静默失效
- `test_inject_js_goes_inside_iife` —— 注入代码落到闭包外，读不到任何变量（连白抓多轮）

**改这些代码前请先读对应测试的 docstring**，它们是踩坑记录。
