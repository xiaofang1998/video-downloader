# 05 部署与排障

## 1. 三种运行方式

### 1.1 打包版（交付给客户/运营）

```
双击 dist\视频下载工具.exe
  → 起本地服务（默认 127.0.0.1:8765）
  → 用 msedge.exe --app 打开界面窗口
  → 关掉窗口即退出程序（日志：logs/desktop.log）
```

首次运行会在 exe 同目录生成 `data/`、`downloads/`、`logs/`、`config.json`。

### 1.2 源码运行

```bat
:: 一键（start.bat 会优先用 venv，其次 uv，最后系统 python）
start.bat serve

:: 或直接用解释器
.venv\Scripts\python.exe run.py serve
```

依赖只有一个：`yt-dlp`（`pyproject.toml`）。**ffmpeg 只在需要 DASH 合流时才要求**，
没有它也能下"单文件流"的站点。

### 1.3 只跑一次（不常驻）

```bat
start.bat once "7.92 复制打开抖音… https://v.douyin.com/xxx/"
```

## 2. 打包

```bat
.venv\Scripts\python.exe build_desktop.py
```

| 行为 | 说明 |
| --- | --- |
| 旧产物 | 自动挪到 `dist/_old/<名字>-<时间戳>`（不会覆盖，可随时删） |
| ffmpeg | 随包打进（含 64 个 DLL，约 131 MB），并**实测可用**才继续打包 |
| 产物 | `dist/视频下载工具.exe`（约 115 MB，单文件） |
| 入口 | `desktop.py`：起服务 + Edge app 模式窗口 |

打包相关的回归测试：`tests/test_build_desktop.py`（ffmpeg 处理逻辑）、
`tests/test_frozen_paths.py`（冻结后 `app_dir/bundle_dir` 不能混 —— 混了就会把数据写进临时解包目录，
重启即丢）。

## 3. 配置

- 文件：exe/源码目录下的 `config.json`（`Config.load` 会在缺文件时写一份默认配置）
- 结构：见 [02 第 5 节](02-架构与代码地图.md)（顶层 `server/paths/net/download/search/resolve/replies/channels/delivery/logging`）
- 读取：`config.get("download.quality")` 点号路径；`Config.copy()` 用于"只对本单生效"的覆盖
- 环境变量：`XYDL_*` 可覆盖（`apply_env_overrides`），例如 `XYDL_CAPTURE_INJECT=1`

**常用几个键：**

```jsonc
{
  "server": { "port": 8765, "token": "本地页面口令，留空不校验" },
  "net":    { "proxy": "auto", "timeout_sec": 20, "verify_tls": true },
  "download": {
    "quality": "best",          // best/1080/720/480/360
    "watermark": "auto",        // auto/off/delogo/any
    "cookies_from_browser": "", // 例如 "edge"
    "series": { "enabled": true, "max_episodes": 50, "mode": "zip" }
  },
  "delivery": { "uploader": "none" }   // none / baidu / s3
}
```

## 4. 日志与现场

| 位置 | 内容 | 什么时候看 |
| --- | --- | --- |
| `logs/desktop.log` | 桌面版启动/退出、窗口连接 | exe 起不来或"自己退了" |
| `logs/boot.log` | 启动引导 | 打包版冷启动问题 |
| 控制台"📜 日志" | 单订单事件流（来自 `data/xydl.sqlite3` 的 `events` 表） | 某单为什么失败 |
| `data/capture_log.txt` | 抓包通道日志（用 `channels-capture` 时生成） | 抓包没截到东西 |
| `run.py doctor` | 代理/引擎/上传/数据库/视频号链路体检 | 环境问题 |

## 5. 排障表

| 症状 | 原因 | 处理 |
| --- | --- | --- |
| 页面打不开 / 提示连接失败 | 服务没起或端口被占 | 看 `logs/boot.log`；换 `server.port`；`run.py doctor` |
| exe 启动后自己退出 | 界面窗口被关掉（设计如此：关窗即退出） | 重新双击；不需要常驻就用 CLI |
| 抖音/TikTok 下载失败，提示先登录 | 没有登录态 | 界面点「🔑 登录抖音/TikTok」或 `run.py cdp-login douyin` |
| 视频号短链下不了 | 短链不带授权 | 按界面引导去**腾讯元宝**解析一次，把带 `token` 的链接粘回来 |
| 视频号提示"元宝未登录" | 元宝会话过期 | `run.py channels-login --yuanbao` 重新登录一次 |
| 下到的是加密文件 | 抓包通道拿到的直链是密文 | 用 `run.py decrypt <文件> -k <decode_key>`，或让 `auto_decrypt` 开着（默认开） |
| 交付的是带水印版本 | 平台只给了带水印地址 | 交付话术里会标注"带水印源"；要干净的可试 `--watermark delogo` |
| 界面能看到但下载 0 字节 | 上游 CDN 403 | 视频号会自动去掉 Referer 重试；其它平台看订单日志里的原始错误 |
| 浏览器 cookie 读不到 | Chrome/Edge 在运行（App-Bound 加密） | 关掉浏览器再试，或导出 `cookies.txt` 配 `cookies_file` |
| 网络整体变慢/异常 | （历史事故）链式代理上游解析错 | 已修；如再出现：`run.py channels-capture --restore` 还原系统代理 |
| 视频号页面打不开 | 用过页面注入（有副作用） | 见 5.1 恢复流程 |

### 5.1 抓包/注入副作用的标准恢复流程

> 注入会改写客户端页面资源，可能让视频号页面打不开。**默认关闭**，只在本机诊断时开。

```bat
:: ① 停服务并还原环境（代理、证书）
run.py channels-capture --restore

:: ② 完全退出微信（托盘右键退出）
:: ③ 清掉 webview 纯缓存目录（不含聊天记录）：
::    %APPDATA%\Tencent\xwechat\radium\web\profiles\<profile>\
::        Code Cache / GPUCache / Cache / Service Worker\CacheStorage
::    %APPDATA%\Tencent\xwechat\radium\cache
:: ④ 重开微信即恢复
```

## 6. 隐私与安全

| 项 | 做法 |
| --- | --- |
| cookie | 代码只记录 **cookie 名**，不记录值；`http.py` 有专门开关 |
| 抓包数据 | 只落在 `data/capture_store.json`、`data/wx_capture.json`，交付前可整体删除 |
| 根证书 | 只在抓包时安装到**当前用户**（不需要管理员），且提供卸载；`--restore` 会清干净 |
| 系统代理 | 抓包时改 HKCU 代理并记录原值；退出/`--restore` 还原；异常退出后启动时会自愈 |
| 登录态 | 存在工具自己的 `browser-login/<platform>/`，与用户日常浏览器**完全隔离** |
| 本地服务 | 默认只监听 `127.0.0.1`；`server.token` 可用于局域网/多用户场景 |

```bat
.venv\Scripts\python.exe -m pytest -q          :: 全绿
.venv\Scripts\python.exe run.py selftest       :: 退出码 0
.venv\Scripts\python.exe run.py doctor         :: 看有没有红项
.venv\Scripts\python.exe build_desktop.py      :: 打包
:: 启动 dist\视频下载工具.exe，粘一条真实链接，确认能下到文件
:: 删掉 dist\data、dist\downloads、dist\logs（别把测试数据带出去）
:: 检查页面上没有第三方服务名（TikHub 等）
```
