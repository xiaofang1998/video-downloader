# 02 架构与代码地图

> 目标：**不看源码也能说清每个文件干什么、谁调用谁、数据落在哪**。
> 本文覆盖 38 个 Python 源文件 + 网页控制台 + 打包脚本。

## 1. 分层架构

```
┌──────────────────────────────────────────────────────────────────────┐
│ 渠道层 xydl/channels/          消息从哪来、回话往哪去                  │
│   console(网页控制台·默认)  inbox(目录收件箱)  xianyu_bridge(闲鱼桥接) │
└───────────────────────────────┬──────────────────────────────────────┘
                                │ IncomingMessage
┌───────────────────────────────▼──────────────────────────────────────┐
│ 流水线 xydl/pipeline.py        一条消息的完整生命周期 + 订单状态机      │
│   receive → 解析链接 → 展开短链/落源 → 多剧集展开 → 下载 → 交付 → 回话  │
└───┬───────────────┬───────────────┬──────────────┬───────────────────┘
    │               │               │              │
┌───▼──────┐  ┌─────▼──────┐  ┌─────▼──────┐  ┌────▼─────────────────┐
│ 识别层    │  │ 解析/展开层 │  │ 下载层      │  │ 交付层               │
│linkparse │  │resolver    │  │downloader  │  │uploaders/            │
│          │  │series      │  │ ├ YtDlp    │  │ ├ baidu(网盘)        │
│          │  │series      │  │ ├ Http     │  │ ├ s3(对象存储)       │
│          │  │            │  │ └ 平台专用 │  │ └ none(仅发文案)     │
└──────────┘  └────────────┘  └─────┬──────┘  └──────────────────────┘
                                    │
        ┌───────────────────────────┴────────────────────────────┐
        │ 平台解析通道（全部自研）                                 │
        │  cdp_fetch(抖音/TikTok)  kuaishou GraphQL(快手)          │
        │  yuanbao + wechat_channels(视频号)  twitter(X)           │
        │  wxdecrypt(视频号解密)   watermark(水印)                 │
        └─────────────────────────────────────────────────────────┘
┌──────────────────────────────────────────────────────────────────────┐
│ 基础设施：config(配置) store(SQLite) models(模型) http(HTTP)          │
│          utils(文件名/文本) cookies(浏览器 cookie) 搜索层 search/     │
└──────────────────────────────────────────────────────────────────────┘
```

**依赖方向**：上层依赖下层，**不允许反向**。
两个已知的环被"函数内导入"打破，改动时别改成模块级导入：

- `wechat_channels` ↔ `wxproxy`：`wechat_channels.resolve_media` 里 `from . import wxproxy`
- `downloader` ↔ `wechat_channels`：下载引擎里按需导入

## 4. 关键数据结构

| 结构 | 位置 | 要点 |
| --- | --- | --- |
| `Order` / `OrderStatus` | `models.py` | 状态机：`received → resolving → downloading → uploading → done / failed / need_manual / cancelled`；`meta` 存**订单级选项**（`quality`/`watermark`/`episode_range`） |
| `LinkCandidate` | `models.py` | 一条候选链接：`url/platform/kind/title/confidence/note` |
| `DownloadResult` | `models.py` | `ok/file_path/title/size_bytes/engine/error/meta`；`meta["watermark"]="带水印源"` 表示用了带水印源 |
| `Episode` / `SeriesPlan` | `series.py` | 一集（`index/url/title/source/object_id/export_id`）与整个计划（`title/episodes/truncated`） |
| `ChannelsRef` / `ChannelsFeed` / `ChannelsMedia` | `wechat_channels.py` | 短码/exportId/token；feed 元数据与候选直链；解析结果（含 `decode_key`、`quality`、`via`） |
| `ChannelsFeed.raw` | `wechat_channels.py` | 原始 `feedInfo`，`feed_media_candidates` 从中列出所有档位 |
| `CaptureStore` 条目 | `wxproxy.py` | `{url, decode_key, title, source(cdn/api/spec/inject), height, label, ts}` |
| `Progress` | `downloader.py` | `percent/stage/speed/eta/downloaded` |

## 5. 配置项速查

顶层键：`server` `paths` `net` `download` `search` `resolve` `replies` `channels` `delivery` `logging`。

**`download`**（下载行为）：

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `quality` | `best` | `best/1080/720/480/360`，按订单可覆盖 |
| `watermark` | `auto` | `auto/off/delogo/any`（见 [03](03-下载链路详解.md) 第 4 节） |
| `prefer_no_watermark` | `true` | 是否优先取无水印源 |
| `delogo_rect` | `""` | 固定水印矩形 `x:y:w:h`，留空按平台预设估算 |
| `prefer_ytdlp` | `true` | 关掉就只用直链下载 |
| `prefer_compatible` | `true` | 优先 H.264/AAC（老设备/剪映友好） |
| `cookies_from_browser` / `cookies_file` | `""` | cookie 来源（二选一） |
| `max_filesize_mb` | `2048` | 超过就拒绝下载 |
| `task_timeout_sec` | `1800` | 单任务整体超时 |
| `series.enabled/max_episodes/episode_range/mode` | `true/50/""/zip` | 多剧集开关、上限、选集、打包方式 |
| `wechat_channels.*` | 见源码 | `use_browser(false)`、`auto_decrypt(true)`、`capture_store`、`yuanbao_enabled(false)`、`yuanbao_headless(false)` |

**`delivery`**：`uploader(none/baidu/s3)`、`mode(share_link/upload_only)`、`link_template`、
`forward_progress`、百度与 S3 各自的凭据、`bridge`（闲鱼上游地址与 token）。

**`net`**：`proxy(auto/system url/…)`、`timeout_sec`、`verify_tls`、`max_bytes`。

## 6. 数据落盘

| 路径 | 内容 | 说明 |
| --- | --- | --- |
| `data/xydl.sqlite3` | 订单、事件、外发消息 | 重启不丢；`events` 就是控制台里"📜 日志"的数据源 |

## 7. 改动时的注意事项（踩过的坑）

| 规则 | 为什么 |
| --- | --- |
| 别把"函数内导入"改成模块级 | `wechat_channels` ↔ `wxproxy` 会成环 |
| `CertAuthority.leaf_for` 必须持锁 | 微信对同一域名并发建连，多线程签同一域名会互相覆盖 key → `KEY_VALUES_MISMATCH` |
| `job_dir` 开跑前必须清场 | 否则上一轮残留文件被"取最大文件"兜底误判为本次成果 |
| 订单级选项走 `meta`，不要改全局配置 | 并发订单会串（选集串单真实发生过） |
| 错误信息必须带下一步动作 | 客户/运营看的是这句话，不是堆栈 |
| 视频号 CDN 403 时去掉 Referer 再试一次 | 社区经验，实测有效（`download_channels_media`） |
| 抓包相关代码一律默认关闭 | 会改用户环境（见 [01 第 5 节 D3](01-需求与范围.md)） |

## 8. 一图看懂一次下载

```
客户消息 ──► channels/console 落成 Order
                    │
        linkparse.parse  ──►  LinkCandidate[]
                    │
        resolver.expand  ──►  落地 URL（短链展开/标题落源）
                    │
        series.plan      ──►  1 集 or N 集（B站合集/分P）
                    │
        downloader.download（读订单 meta 的 quality/watermark）
             ├─ 视频号：yuanbao → wechat_channels.resolve_media → wxdecrypt
             ├─ 抖音/TikTok：cdp_fetch（页面自身签名请求）
             ├─ 快手：GraphQL visionVideoDetail
             ├─ X：twitter.fetch_media（镜像兜底）
             └─ 其它：YtDlpEngine（格式链）→ HttpEngine
             └─ watermark：候选排序 → 必要时 delogo
                    │
        uploaders（baidu/s3）──► 分享链接
                    │
        replies ──► 粘回客户的话 ──► outbox / 控制台展示
```
