# 03 下载链路详解

> 本文回答两个问题：**每个平台到底怎么拿到视频**、**为什么不能那么做**（已证伪的路径写在第 6 节，避免重复踩坑）。

## 1. 端到端时序

```
买家消息
  │  linkparse.parse            切链接 / 判平台 / 猜标题
  ▼
LinkCandidate[] ── resolver.expand ──► 落地 URL（短链展开、标题落源、鉴权墙识别）
  │
  ▼
series.plan                     1 集还是 N 集？（B站合集/分P；视频号老实按单集）
  │  ① 订单级选集 episode_range（只对本单生效）
  ▼
downloader.download             ← 读订单 meta 的 quality / watermark
  │      └─ _download_inner     按平台分派（见下）
  ▼
交付：uploaders（网盘/对象存储）→ replies 生成回话 → 控制台/闲鱼推送
```

**两级降级**：先 `YtDlpEngine`（能处理视频页、DASH 合流、HLS），失败再 `HttpEngine`（直链）。
视频号与抖音/TikTok/快手**不放进这条链**，因为它们走专用通道，放在里面只会白跑几十秒并给出误导性报错。

## 2. 各平台解析链

### 2.1 B站（含合集/分P）

```
BV 链接 / b23.tv 短链
  │
  ├─ series.bilibili_season_episodes(url)       ← 公开 view 接口
  │     GET https://api.bilibili.com/x/web-interface/view?bvid=BV…
  │       data.ugc_season.sections[].episodes[]   → 整部合集（每集 bvid + 标题）
  │       data.pages[]                            → 多分P
  │     命中就展开成 N 集（不再靠 yt-dlp 猜）
  │
  └─ 回退：yt-dlp --flat-playlist -J（只取条目清单，50 集一次请求）
```

**为什么先用 view 接口**：yt-dlp 拿到单个 BV **只会返回那一集**，看不到合集 —— 用户"粘了合集里的一集，
结果只下了一集"就是这么来的。view 接口一次请求就把整个合集给全了。
（`test_bilibili_view_api_returns_whole_season` 钉住。）

分P 链接的 `?p=N` 在探测时会**去掉**，否则 yt-dlp 只返回第 N 集、看不到整部
（`test_page_param_url_probes_whole_playlist`）。

### 2.2 抖音 / TikTok（自研登录态 CDP）

```
分享链接 → login_profile_dir(platform) 存在吗？
  ├─ 不存在 → 明确报错"先登录一次"
  └─ 存在   → cdp_fetch.fetch_douyin_video(url, profile)
        在工具自己的 Edge profile 里打开页面，
        截页面**自己带签名（a_bogus 等）**发出的媒体请求 → 拿无水印直链
```

**为什么这么绕**：这两家现在对请求签名（`a_bogus`），本地复现签名不现实、yt-dlp 解析器已过时
（实测 `403 Uifid Not Found`）。**截页面自己的请求**是最稳的做法，而且拿到的就是无水印直链。

### 2.3 快手（自研 GraphQL）

```
v.kuaishou.com 短链 → GraphQL visionVideoDetail → photoUrl（无水印播放源）
```

`downloader.kuaishou_photo_url()` 负责；被风控拦截时提示"先用浏览器访问一次快手"。

### 2.4 微信视频号（元宝链路 + 抓包兜底）

```
/sph/xxx 短链（不带授权，服务端不下发媒体）
  │
  ├─ ① 元宝链路（推荐，零侵入）
  │     把短链发给腾讯元宝 → 它回一条
  │       channels.weixin.qq.com/finder-preview/pages/feed?token=…&eid=…
  │     把该链接粘回本工具
  │       → POST /finder-preview/api/feed/get_feed_info
  │           body {"baseReq":{"generalToken":<token>},"exportId":<eid>}
  │       → data.feedInfo.h264VideoInfo.videoUrl    明文 MP4（不需要解密）
  │
  ├─ ② 本地抓包兜底（可选，默认关）
  │     run.py channels-capture：只在视频号相关域名做 MITM
  │       截到 stodownload 直链 + decode_key + spec[]（分辨率档位）
  │       抓到的直链是**加密**的 → wxdecrypt 解前 128 KiB
  │
  └─ ③ 登录态浏览器抓取：实测无效，默认关（见第 6 节）
```

关键事实（都实测过）：

- **`token` 是唯一的钥匙**：同一个接口，`generalToken` 传空 → 服务端**剥离媒体字段**，只剩标题/封面。
- **签名 URL 的 `basedata` 是"该 URL 允许的清晰度档位白名单"**：把 `base64` 解出来只有
  `['xWT113']`（h264）/ `['xWT258']`（h265）—— 白名单里只有一个档，所以**改 `X-snsvideoflag` 也拿不到别的分辨率**。
- **CDN 要求完整签名**：只留 `encfilekey`+`token`（去掉 `basedata`/`sign`）→ HTTP 400。
- **同一份视频给两种编码**，工具**优先 h264**（兼容性优先，`_media_from_feed_dict` 的老行为保留）。

### 2.5 X / Twitter

```
x.com/<user>/status/<id>
  ├─ yt-dlp 能解析就直接用（元数据全）
  └─ yt-dlp 报 "No video could be found in this tweet"（受限推文：需登录/年龄门槛）
       → twitter.fetch_media：api.fxtwitter.com（失败自动降级 api.vxtwitter.com）
           → tweet.media.videos[].url（video.twimg.com 直链，**不需要登录**）
```

**判据**：报错文案里出现"no video could be found"就说明游客态拿不到 media，直接走镜像。
镜像返回有两种结构（`tweet.media.videos` 与 `mediaURLs`/`media_extended`），解析都兼容；
多条视频按**总像素**排序取最优（只按 height 排会把竖屏低清排到前面，踩过）。

### 2.6 其它平台

| 平台 | 通道 |
| --- | --- |
| 小红书 | yt-dlp（带不带 cookie 都行） |
| YouTube | yt-dlp（**千万别带 cookie**，会触发风控） |
| 微博/西瓜 | yt-dlp（西瓜解析器上游失效，等修复） |
| 任意 `…mp4` 直链 | `HttpEngine` 直接下 |
| 腾讯视频/爱奇艺/优酷/芒果TV | 按设计拦截（DRM） |

## 3. 清晰度策略

**yt-dlp 站点**：`YtDlpEngine._format_chains(quality)` 给出**多套降级链**，前一套失败换下一套：

```
有 ffmpeg + 兼容优先：  bv*[vcodec^=avc1][height<=N]+ba[acodec^=mp4a] / …
有 ffmpeg：            bv*[height<=N]+ba/b[height<=N]/b
兜底：                 bv*+ba/b → bv*+ba → b（单文件流）
无 ffmpeg：            b[height<=N][ext=mp4]/b[height<=N]/b
```

为什么要有"兼容编码"那一档：YouTube 默认给 AV1+Opus，但交付给客户的文件得能在老手机/剪映里播。

**视频号**：`feed_media_candidates()` 列出这条 feed 的**所有**档位，`pick_media_candidate(quality)` 按偏好挑：

- `1080`/`720`/`480` → 有 `spec[]`（客户端抓包才有真实分辨率）时挑"最接近且不低于"的档；
- 没有分辨率信息（纯 HTTP 只有一档）→ 退化成编码偏好：`compatible/best`→h264，`small/worst`→h265；
- 站点没有该档位 **自动降级**，不会为了"必须 1080"直接失败。

## 4. 水印策略

两层，默认只做第一层：

**① 取无水印源（无损，默认）**

```
候选地址 ──► watermark.order_candidates()
               · 识别带水印特征（playwm / watermark=1 / with_watermark=1 …）
               · 改写为干净候选（playwm→play、watermark=1→0）
               · 排序：干净版在前，带水印原地址兜底在最后
           ──► Downloader._try_candidates()  **按顺序试**
               · 干净版常常是"改写"出来的，平台不保证存在 → 失败自动退回带水印版
               · 真用了带水印地址 → result.meta["watermark"] = "带水印源"（如实标注）
```

**② 像素级擦除（有损，必须显式选择）**

`--watermark delogo` 或 `run.py delogo`：ffmpeg `delogo` 用周边像素插值覆盖水印区域。
预设按平台（水印都在右下角，比例估算）；`--rect x:y:w:h` 可精确指定；`--dry-run` 先看矩形。
默认另存 `xxx.nowm.mp4`，`--in-place` 才覆盖。

## 5. 失败时的降级与话术

| 环节 | 失败表现 | 处理 |
| --- | --- | --- |
| 链接识别 | 没有链接 | 用标题去搜索引擎落源；找不到就如实回复 |
| 短链展开 | 跳转链断裂 | 记下跳转链，报"落地地址"给运营 |
| 下载（yt-dlp） | 缺 cookie | 自动读本机浏览器 cookie 重试一次；仍失败就提示登录 |
| 下载（抖音/TikTok） | 没登录过 | 提示"先登录一次"，不报看不懂的错 |
| 视频号 | 短链没 token | 提示用元宝解析一次，并把步骤写进错误文案 |
| 视频号 | 只有 object_id | 明确说明"只能按 object_id 定位，请用元宝解析出带 token 的链接" |
| 视频号 CDN | 403 | **去掉 Referer 再试一次**（实测有效） |
| 视频号产物 | 前 128 KiB 是密文 | 自动解密；解不开就**明确失败**，绝不交付坏文件 |
| 水印 | 只要无水印但平台只有带水印版 | `off` 模式直接报错；`auto` 模式照常交付并标注 |

## 6. 已证伪的做法（别再试）

> 下面每条都是**实测**结论，附现象，避免以后重复投入。

### 6.1 视频号

| 尝试 | 结果 |
| --- | --- |
| 匿名请求 `/web/pages/*` | `{"errCode":10012 非法请求}`；带视频号助手登录态也拿不到媒体请求 |
| `/web/api/feed/detail` | `{"errCode":-10000,"errMsg":"LoadCtx failed -2"}` |
| `/web/api/feed/get_comment_list` | `{"errCode":1,"errMsg":"Forbidden resource"}` |
| 客户端 cgi `/cgi-bin/micromsg-bin/ilink_findergetcommentdetail`（cmdid 6225） | `Cannot POST` —— 需要微信原生桥签名，纯 HTTP 打不通 |
| 预览页 `/finder-preview/pages/sph?id=…`（登录态） | 只渲染封面 + 二维码，整页 28 个请求无任何视频请求 |
| `Bearer` 形式复用 TikHub 的端点 | 405（已随 TikHub 一起移除） |
| 封面 URL 换成视频路径（`/20350/`→`/20302/`） | HTTP 400 |
| 改/删 `X-snsvideoflag`（试了 10 个档位 + 无标记） | 仍 206 + 720p —— 签名白名单里只有一个档 |
| 只留 `encfilekey`+`token`（去掉 `basedata`/`sign`） | HTTP 400 —— CDN 要求完整签名 |

### 6.2 通用

| 尝试 | 结果 |
| --- | --- |
| 微信 PC 客户端流量做 MITM（3.9） | 原生网络栈自带根证书列表，客户端直接 `UNEXPECTED_EOF` 断开 |
| 微信 PC 客户端流量做 MITM（4.1） | **可行**（CEF 认系统证书库），能截到页面 HTML 与 CDN 请求 |
| 往页面注入 JS 取 `decodeKey` | 可行但**有副作用**：改页面/worker 行为会导致视频号页面打不开（需清 CEF 缓存恢复），因此**默认关闭** |
| 用 CDP 远程调试端口读页面对象 | `WeChatAppEx.exe` 里 `remote-debugging-port` 出现 0 次、无 `DevToolsActivePort`；监听端口是内部 IPC（`/json/version` 空响应）→ 不可行 |
| 视频号"自动列出整部剧" | 没有公开的匿名作品列表接口；`list_series` 如实降级为"把各集链接一起粘进来" |
| 用 AI inpaint 擦水印 | 需要 torch + 模型 + GPU，单文件 exe 会从 115 MB 涨到 500 MB+（见 [01 D5](01-需求与范围.md)） |

### 6.3 抖音/TikTok/快手

| 尝试 | 结果 |
| --- | --- |
| yt-dlp 直解（带/不带 cookie） | `403 Uifid Not Found` —— 签名（`a_bogus`）过不去 |
| 第三方付费解析（TikHub） | 曾可用，但引入付费单点依赖，已按 [D1](01-需求与范围.md) 移除 |
